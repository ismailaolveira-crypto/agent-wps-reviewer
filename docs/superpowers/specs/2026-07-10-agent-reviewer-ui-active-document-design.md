# Agent WPS Reviewer UI 与当前文档连接设计

日期：2026-07-10
目标平台：macOS，WPS Office 12.1.25895
状态：用户已确认交互与架构，等待书面规格复核

## 1. 目标

把现有 WPS 侧边栏改成轻量、清晰的审阅收件箱，并让本机 Codex、Claude Code 等 Agent 自动识别、读取和定位到指定的 WPS 文字文档。

使用者在 Agent 对话中说“修改这篇文章”时，Agent 先列出所有已打开文章，按标题或路径确认目标，不把当前活动文档误当成目标。Agent 读取目标 WPS 文档，生成结构化建议并投递到对应侧边栏。侧栏按建议绑定的句柄激活目标文章后再定位或写入；接受只生成真实 WPS 批注，不修改正文。

## 2. 已确认的产品决策

- 侧边栏使用单栏“建议列表 + 底部详情”结构。
- 点击任意建议卡，底部详情切换到该建议。
- 每条建议只有“定位”“拒绝”“接受”三个操作。
- 接受只生成一条真实 WPS 批注，不替换正文。
- 拒绝后卡片从待处理列表消失。
- 侧边栏获得焦点时，`Command+Z` 可以撤销最近的拒绝。
- Agent 默认列出所有打开的 WPS 文档；活动文档只作为默认展示，不替代用户选择的目标文章。
- Agent 与插件优先通过 MCP 连接；其他本机 Agent 可使用带密钥的 HTTP 接口。
- 正文按需读取，不持续保存到 bridge 数据文件。

## 3. 范围

### 3.1 本版本包含

- 苹果式冷灰、单一蓝色强调的侧边栏视觉重构。
- 待处理与全部两个视图。
- 紧凑建议卡与固定底部详情区。
- 定位、拒绝、接受及拒绝撤销。
- WPS 当前文档发现、切换监听与按需正文读取。
- 大文档分段读取。
- 文档版本指纹与过期建议保护。
- MCP 工具升级与本机密钥保护。
- 浏览器自动化测试、Node 测试和真实 WPS 前台验收。

### 3.2 本版本不包含

- 侧边栏内置 AI 聊天。
- 直接替换正文或自动静默修改。
- 云端多人协作队列。
- WPS 重启后的插件撤销历史。
- 对表格、文本框、脚注等非连续正文结构的完整语义还原。
- Windows 和 Linux 的正式兼容性承诺。

## 4. 使用流程

1. 使用者在 WPS 中打开多篇文章。
2. WPS 加载项枚举并持续注册所有打开文档，只上报文档元数据，不上报正文。
3. 使用者在 Codex 等 Agent 中说“检查这篇文章的数据错误并提出批注”。
4. Agent 调用 `list_wps_documents` 按标题或路径选择目标文档，再取得该文档元数据和版本指纹。
5. Agent 分段读取正文并完成分析。
6. Agent 批量提交结构化建议，同时携带文档句柄和版本指纹。
7. bridge 校验目标文档与版本，把建议写入对应文档队列。
8. WPS 侧边栏通过 SSE 实时显示建议。
9. 使用者点击卡片，在底部详情查看原文片段和批注意见。
10. 使用者选择定位、拒绝或接受；侧栏按目标句柄自动激活对应文章。

## 5. 系统架构

```text
Codex / Claude Code / Other Agent
  -> MCP stdio / authenticated localhost HTTP
  -> Local bridge command queue
  -> WPS add-in background page
  -> WPS Application.Documents / ActiveDocument
  -> document metadata / text chunk response

Agent
  -> submit_wps_suggestions(documentHandle, revisionToken, suggestions[])
  -> ReviewStore
  -> SSE document queue
  -> WPS task pane
  -> Range.Select / Comments.Add
```

### 5.1 组件边界

#### WPS 后台连接器

运行在加载项后台页面中，负责：

- 监听 `WindowActivate`、`DocumentChange`、`DocumentViewFocusIn` 事件，并枚举打开的 WPS 文字文档。
- 维护所有打开文档及最近激活标记。
- 响应 bridge 的按需读取命令。
- 响应 bridge 的目标文档激活命令。
- 读取 `ActiveDocument.Content.Text`、当前选择区和文档元数据。
- 计算文档版本指纹。
- 不保存正文；只有收到侧栏针对某条建议的激活命令时切换目标文档，不主动抢夺窗口焦点。

#### Local bridge

负责：

- 保存文档元数据、建议状态和验收事件。
- 维护 WPS 客户端心跳和命令队列。
- 把 MCP 的读取请求按目标句柄转给对应 WPS 客户端，并等待响应。
- 把侧栏的目标激活请求转给对应 WPS 客户端，并校验返回句柄。
- 校验文档句柄、版本指纹和 Agent 权限。
- 向对应侧边栏推送建议更新。

bridge 不把正文写入 `review-store.json`。读取响应只在当前请求内存中存在，请求完成或超时后释放。

#### MCP server

负责把 Agent 工具调用转换为 bridge 请求。它不直接控制 WPS，不自行保存正文。

#### WPS task pane

负责展示、定位、拒绝、接受和撤销。它不承载 AI 聊天，也不保存 API Key。

## 6. 当前文档识别

### 6.1 激活规则

- WPS 文档窗口触发激活或获得正文焦点时，记录为最近激活文档。
- 使用者切换到 Codex 后，目标仍保持为最后一篇获得 WPS 焦点的文档。
- 同时打开多篇文档时，目录返回全部仍在线的文档，按活动状态排序；Agent 必须按标题或路径选择目标句柄。
- 如果 WPS 心跳超过 10 秒未更新，Agent 读取返回“当前没有可用的 WPS 文档”。

### 6.2 文档句柄

`documentHandle` 只在当前 WPS 运行期间稳定。它由后台连接器为已打开文档生成，不使用文件名作为唯一键。

句柄生成依据：

- 已保存文档：规范化 `FullName` 与当前 WPS runtime id。
- 未保存文档：WPS runtime id、窗口标识和加载项生成的随机 id。

WPS 重启后生成新句柄，旧句柄不能继续投递。

### 6.3 版本指纹

读取正文时生成 `revisionToken`，内容为文档句柄、正文长度和正文 SHA-256 的组合。

Agent 提交建议必须携带读取时得到的 `revisionToken`。bridge 或 task pane 在展示和接受前重新校验：

- 指纹一致：允许处理。
- 指纹不一致：建议标记为过期，不生成批注，提示 Agent 重新读取。

批注本身不改变正文指纹。

## 7. MCP 工具设计

### 7.1 `list_wps_documents`

列出所有仍在线的打开文档，返回 `documentHandle`、标题、路径、版本、活动状态和心跳时间。不返回正文。该工具是多文章工作流的第一步。

### 7.2 `get_active_wps_document`

返回：

```json
{
  "documentHandle": "wpsdoc_xxx",
  "title": "文章.docx",
  "textLength": 18024,
  "selectionText": "",
  "revisionToken": "sha256:xxx",
  "lastActiveAt": "2026-07-10T10:00:00.000Z"
}
```

该工具不返回完整正文。

### 7.3 `read_wps_document`

输入：

```json
{
  "documentHandle": "wpsdoc_xxx",
  "offset": 0,
  "limit": 32000
}
```

单次最多返回 32,000 个字符，并返回 `nextOffset`、`done` 和 `revisionToken`。Agent 读取下一段前必须确认指纹未变化。

### 7.4 `submit_wps_suggestions`

输入包含：

- `documentHandle`
- `revisionToken`
- `sourceAgent`
- `threadId`
- `suggestions[]`

每条建议至少包含：

- `anchorText`
- `comment`

可选包含：

- `contextBefore`
- `contextAfter`
- `severity`
- `category`

本版本允许兼容接收 `replacement` 和 `reason`，但侧边栏不展示，也不执行替换。

### 7.5 兼容工具

保留 `list_wps_suggestions`。旧的 `submit_wps_suggestion` 继续可用，但标记为兼容入口；新 Agent 默认使用批量工具。

## 8. 侧边栏 UI

### 8.1 视觉规则

- 背景：`#F5F5F7`。
- 卡片：白色，1px 冷灰边框，8px 圆角，无渐变、无装饰阴影。
- 文字：系统字体栈，正文 `#1D1D1F`，辅助文字 `#6E6E73`。
- 强调色：仅使用 Apple blue `#0071E3`。
- 危险操作：拒绝文字使用 `#D70015`，不使用红色大面积填充。
- 动效只用于选中、详情切换和卡片移除，时长 120-180ms。
- 支持 320px、360px、420px 和 480px 侧边栏宽度。

### 8.2 页面结构

```text
Agent 审阅                         刷新
[ 待处理 n ] [ 全部 ]

[类别] 建议标题                     >
       一行摘要
[类别] 建议标题                     >
       一行摘要

--------------------------------------
选中建议标题                         关闭
正文片段
批注意见
[定位] [拒绝] [接受]
```

不再显示：

- 会话输入框与复制按钮。
- 独立详情栏。
- 建议替换和理由区块。
- 应用修改按钮。
- 浏览器模拟文档区块。

浏览器模拟模式保留为开发路由，不进入 WPS 正式侧边栏布局。

### 8.3 卡片与底部详情

- 卡片显示类别、标题和一行摘要。
- 点击卡片后增加细蓝色描边。
- 底部详情重复显示选中卡片标题，避免对应关系不清。
- 底部详情固定在侧边栏底部，内部内容超长时独立滚动。
- 关闭详情后保留列表，不清除选中建议。

## 9. 操作状态机

### 9.1 状态

界面状态：

- `pending`：待处理。
- `accepted`：已接受。
- `rejected`：已拒绝。
- `stale`：正文版本已变化。
- `conflict`：无法定位正文。

数据层暂时沿用现有 `commented` 存储已接受状态，界面映射为“已接受”，避免已有数据迁移。数据层新增 `stale`；`accepted` 仅是界面名称。按钮处理中是瞬时 UI 状态，不写入持久化状态。

“待处理”视图包含仍需人工处理的 `pending`、`conflict` 和 `stale`，因此定位失败或正文变化不会让卡片意外消失。

### 9.2 定位

1. 重新读取当前文档句柄和正文。
2. 校验文档与建议目标一致。
3. 使用 `anchorText` 精确匹配；重复片段用前后文评分；WPS Range 只允许 CR/LF 换行编码差异，不放宽锚点边界字符。
4. 调用 `Range.Select()`。
5. 状态保持不变。

找不到正文时不改变文档，将建议标记为 `conflict` 并显示“未找到对应正文”。

### 9.3 拒绝

1. 锁定当前卡片操作。
2. 更新 bridge 状态为 `rejected`。
3. 成功后从待处理列表移除，并进入全部视图。
4. 把建议 id 压入当前文档的内存撤销栈。
5. 显示“已拒绝这条建议｜撤销 · Command+Z”。

如果更新失败，卡片恢复原位并显示错误。

### 9.4 拒绝撤销

- 只有侧边栏自身获得焦点时才监听 `Command+Z`。
- 只有最近的插件操作是拒绝时才拦截快捷键。
- 连续拒绝多条时，连续撤销按相反顺序恢复。
- 撤销把状态改回 `pending`，并按原创建时间恢复列表位置。
- 点击提示中的“撤销”和按快捷键执行相同行为。
- WPS 或侧边栏重启后不保留撤销栈；拒绝记录仍保留在全部视图。

### 9.5 接受

1. 生成唯一 `operationId` 并锁定卡片按钮。
2. 校验当前文档句柄和版本指纹。
3. 重新定位正文锚点。
4. 调用 `Comments.Add` 生成真实 WPS 批注。
5. 成功后将状态更新为 `commented`，界面显示“已接受”。
6. 从待处理列表移除，进入全部视图。

接受不会设置 `Range.Text`，不会开启修订，不会修改正文。

为防止“批注已生成但 bridge 状态提交失败”导致重复批注，侧边栏把成功的 `operationId` 和建议 id 写入本地操作日志。网络恢复后只重试状态提交，不再次调用 `Comments.Add`。状态提交成功后清除日志。

适配器同时记录批注指纹，包括建议 id、锚点范围和批注文本摘要。侧边栏重新打开、刷新或收到文档变化事件时会核对批注是否仍存在。如果使用者在 WPS 正文中用原生撤销删除了该批注，建议恢复为 `pending`，避免“批注已不存在但插件仍显示已接受”。

## 10. 全部视图

- 显示待处理、已接受、已拒绝、过期和冲突建议。
- 默认按创建时间倒序排列。
- 每张卡显示明确状态标签。
- 已接受项只读，不再次生成批注。
- 已拒绝项可以查看详情，但本版本不提供长期“恢复到待处理”按钮；即时恢复使用撤销提示或 `Command+Z`。
- 待处理视图按创建时间倒序显示未解决建议。

## 11. 错误处理

- WPS 未运行：Agent 返回“当前没有可用的 WPS 文档”。
- 插件未连接：Agent 返回“WPS 插件未连接，请确认 Agent 审阅加载项已启用”。
- 多文档切换：使用最近激活文档；提交目标不是当前文档时拒绝处理。
- 正文变化：返回过期错误并要求 Agent 重新读取。
- 文档读取超时：5 秒后失败，不返回旧缓存正文。
- 锚点缺失：保留卡片并显示冲突。
- 批注 API 失败：保留待处理状态，允许重试。
- bridge 状态提交失败：保留本地操作日志，不重复生成批注。
- SSE 断开：显示低干扰离线状态并自动重连，已有卡片仍可查看但操作禁用。

错误信息使用可行动语言，不显示原始异常堆栈。

## 12. 安全与隐私

- bridge 仅监听 `127.0.0.1`。
- 安装时生成随机 Agent token，保存为仅当前用户可读的本机文件。
- 文档读取、命令和 Agent 投递接口必须验证 token。
- MCP stdio server 自动读取本机 token，普通使用者不手工填写。
- WPS 页面使用同源和安装级凭证访问插件接口。
- 移除宽泛的 `Access-Control-Allow-Origin: *`，只允许加载项自身来源。
- 正文不写入 ReviewStore、日志、验收事件或错误信息。
- Agent 获取正文后是否发送到外部模型由该 Agent 的模型配置决定，插件安装说明必须明确提示。

## 13. 性能约束

- 后台事件只更新元数据和失效标记，不在每次键入时上传全文。
- `DocumentChange` 事件做 300ms 防抖。
- 全文和 SHA-256 只在 Agent 读取或处理建议前按需计算。
- 单次 MCP 文本响应最多 32,000 字符。
- 侧边栏建议列表超过 100 条时采用分段渲染或虚拟化。
- 后台连接器不得主动激活 WPS 窗口。

## 14. 验收标准

### 14.1 自动化测试

- 当前文档注册、激活切换、心跳过期和关闭清理。
- 文档句柄在同一运行期稳定，WPS 重启后失效。
- 大文档分段读取、边界和版本变化中断。
- MCP 工具 schema、授权、超时和错误返回。
- 建议投递目标与版本校验。
- 拒绝、连续撤销、撤销失败恢复和列表顺序。
- 接受操作锁与本地操作日志，证明不会重复调用批注。
- WPS 原生撤销删除已接受批注后的状态对账。
- UI 在 320、360、420、480px 宽度下无溢出和重叠。
- 空状态、加载状态、离线状态、冲突状态和长文本状态。

### 14.2 真实 WPS 验收

- 新建空白文档后顶部可见“Agent 审阅”标签。
- 打开侧边栏后显示新的单栏 UI。
- Codex 无需会话编号即可获得当前文档标题与正文。
- 同时打开两篇文档并切换后，Codex 读取到最近激活的正确文档。
- Agent 提交的建议只出现在目标文档。
- 定位选中正确原文；重复锚点使用上下文定位。
- 接受只生成一条真实批注，正文内容不变。
- 在 WPS 正文中原生撤销该批注后，建议恢复为待处理。
- 双击或断网重试不会生成重复批注。
- 拒绝后卡片消失，侧边栏内 `Command+Z` 恢复。
- WPS 关闭、bridge 断开、正文变化时均不投错文档。
- 后台运行期间不弹窗、不抢焦点、不切换文档。

真实 WPS 验收必须由使用者可见地完成；后台测试通过不能代替前台验收。

## 15. 交付结果

- 安装后 WPS 空白文档可见“Agent 审阅”。
- Codex MCP 已配置，可直接调用当前 WPS 文档工具。
- bridge 作为当前用户的本机后台服务运行。
- 用户无需理解会话编号、端口或 token。
- 交付文档包含安装、卸载、Agent 连接、隐私边界和故障诊断说明。
